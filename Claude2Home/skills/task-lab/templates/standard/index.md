## Порядок чтения при старте сессии

1. `Context/00-START-HERE.md` — цель, границы, инварианты.
2. `steps.md` — история и указатель: найти `Steps/Step-XX.md` без парного `Step-XX-result.md`.
   Если такого нет — открытого шага нет, ждём запроса пользователя.
3. Открытый `Steps/Step-XX.md`, если он есть, и только нужные ему файлы.
4. `Knowledge/README.md` — что уже установлено (`F-NN`) и что ещё гипотеза (`H-NN`).
5. `env.json` — указатель на внешнюю базу знаний (`external_knowledge`); если путь не
   пуст, читать её реестр по тегам, записи цитировать текстом с датой, не ссылкой.
6. `Context/10-repo-and-revisions.md` — авторитетный предмет, ревизии, готовые команды.
7. `Context/20-code-map.md` — куда идти за конкретным материалом.
8. `Context/30-method.md` — критерии факта, гипотезы и приёмки в этой задаче.

Если сессия оборвалась и нужно быстро вернуться — `Context/90-session-restore.md`, а до чтения
файлов:

```bash
python3 <skill>/scripts/restore_task.py {{TASK_ID}}
```

## Что где лежит

| Папка | Назначение | Читает |
|---|---|---|
| `Context/` | служебное: границы, метод, карта предмета, очередь, восстановление сессии, скрипты расчётов в `tools/` | только ИИ |
| `Knowledge/` | реестр утверждений. Один файл — одно утверждение. `F-NN` — проверено, `H-NN` — гипотеза | оба |
| `Steps/` | пары «шаг + результат»: `Step-XX.md` — план по запросу пользователя, `Step-XX-result.md` — вердикт и чего шаг не сделал | оба |
| `Results/` | деливерабл. Самодостаточно: ссылок на реестр и на пути этой папки быть не должно | заказчик |
| `Notes/` | черновые заметки и журналы наблюдений; источником истины не является | оба |
| `Logs/` | сырой машинный вывод: `.log`, `.trace`, `.xcresult`, `.csv`, `.har`. Лежит в корне рядом с `Notes/`, не внутри неё; источником истины не является | оба |
| `Inbox/` | входные материалы | **временная** |
| `steps.md` | история шагов по убыванию плюс указатель на текущий шаг | заказчик |
| `env.json` | указатель на внешнюю базу знаний проекта; пустая строка — базы нет | оба |
| `README.md` | состояние и навигация | заказчик |

## Жёсткие правила

1. **`Inbox/` — не источник истины и не место для ссылок.** Всё полезное вытаскивается в
   `Knowledge/` как гипотеза и проверяется по авторитетному предмету. Ссылаться на `Inbox/` из
   `Knowledge/`, `Steps/`, `Context/` и особенно `Results/` запрещено; папка удаляется после
   закрытия задачи — только с разрешения пользователя.
2. **`Results/` не знает про `F-NN` и `H-NN`.** Деливерабл копируется наружу, где ни реестра, ни
   путей этой папки нет. Нужный контекст — дублировать текстом.
3. **Шаг создаётся только по запросу пользователя.** Пользователь описывает, что нужно сделать; на
   это заводится `Steps/Step-XX.md` со следующим свободным номером — и только потом начинается
   работа. Закончил (или отменил, или упёрся в блокер) — пиши `Steps/Step-XX-result.md` и первой
   строкой в `steps.md`. Открытый шаг ровно один: `Step-XX.md` без парного результата. Будущие шаги
   заранее не создаются и не нумеруются — кандидаты живут в `Context/40-queue.md`.
4. **Меняешь файл — заводи шаг; отвечаешь в терминал — не заводи.** Любая правка отчёта, реестра,
   контекста или кода по запросу пользователя оформляется парой «шаг + результат», даже если это
   одна строка: маленький запрос — маленькая пара, но пара. Вопрос, ответ на который целиком
   помещается в реплику — «что сделано», «где лежит», «почему так», чтение предмета, прогон
   аудита, — шагом не оформляется. Исключений ровно три: черновик в `Notes/`, сырой вывод в
   `Logs/` и запись дрейфа в `Context/90-session-restore.md` при возобновлении сессии. Если по ходу
   ответа выясняется, что нужно что-то поправить, — сначала план шага, потом правка.
5. **Если шагу нужен выбор — предлагать одну правку с обоснованием**, а не таблицу кандидатов.
6. **Гипотеза не становится фактом без доказательства** с областью действия. В факте отдельно
   выписывать, что именно не проверено.
7. **Мусор и отклонённые версии не хранить.** Опровергнутая гипотеза остаётся только если её
   опровержение экономит работу будущему читателю.
8. Расчёты — скриптом в `Context/tools/`, в тексте формула с числителем и знаменателем.
