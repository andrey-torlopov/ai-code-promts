- INV-2. **{{FILL_FORBIDDEN_CHANGE_OR_COMPARISON}}** — иначе проверка перестаёт отвечать на вопрос задачи.
- INV-3. **Шаг создаётся только по запросу пользователя; открытый шаг ровно один** — `Steps/Step-NN.md` со статусом «выполняется» и без блока «Результат». Будущие шаги заранее не создаются и не нумеруются.
- INV-4. **Любая правка долговечного файла по запросу — это шаг, даже на одну строку; вопрос с ответом в реплике шага не создаёт.** Иначе история перестаёт объяснять, как папка пришла к текущему виду. Исключений два: черновик в `Notes/`, сырой вывод в `Logs/`.
- INV-5. **Одно причинное изменение на один гейт** — иначе вердикт неатрибутируем.
- INV-6. **Числа: числитель / знаменатель = результат**, с единицами и областью действия; расчёты — скриптом в `tools/`.

## Устройство папки и порядок чтения

```text
README.md      ← вы здесь: состояние, правила, дрейф-чек, история, очередность
env.json       указатель на внешнюю базу знаний; пустая строка — базы нет
Knowledge/     реестр фактов F-NN и гипотез H-NN, по одному утверждению на файл
Steps/         Step-NN.md — один файл на шаг: запрос, план, что сделано, результат, знания
Results/       самодостаточный деливерабл: читается без остальной папки
tools/         скрипты задачи: читатели, калькуляторы, анализаторы
Notes/         черновики и журналы наблюдений; не источник истины
Logs/          сырой машинный вывод: логи, трейсы, профили; рядом с Notes/, не внутри
Inbox/         входные материалы — временная папка, к удалению
```

Порядок чтения при старте сессии:

1. `restore_task.py {{TASK_ID}}` — ограниченный бриф;
2. этот файл целиком — состояние, правила, дрейф-чек, история, очередность;
3. открытый `Steps/Step-NN.md`, а если его нет — последний закрытый шаг (чекпойнт: вердикт и
   задействованные знания);
4. `Knowledge/README.md` — при смене направления или после тупика;
5. только файлы, названные планом шага; внешняя база — по `env.json`, если указатель не пуст.

**Как идёт работа.** Вы описываете, что нужно сделать. На запрос создаётся `Steps/Step-NN.md` со
статусом «выполняется»: запрос, границы, действия и критерий завершения фиксируются до работы. По
завершении в тот же файл дописываются «Что сделано», «Результат» (вердикт первой строкой) и
«Задействованные знания» (какие F/H участвовали и в какой роли), строка шага встаёт первой в
таблицу «Шаги», обновляются строка состояния и очередность. Отмена и блокер — тоже честные
вердикты, закрывающие шаг.
