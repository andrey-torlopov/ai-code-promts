# Spec Review Checklist

Review the written spec before handoff.

Status: `Approved` or `Issues Found`.

Check:

| Category | What to look for |
|---|---|
| Completeness | Missing sections that block planning |
| Placeholders | Unresolved placeholders, `TODO`, `TBD` |
| Consistency | Requirements that contradict each other |
| Clarity | Ambiguous requirements with multiple plausible interpretations |
| Scope | More than one independent subsystem in a single spec |
| YAGNI | Features not requested and not needed for the goal |

Only block on issues that would cause real planning or implementation mistakes.

Output:

```text
Spec Review
Status:
Issues:
Recommendations:
```
