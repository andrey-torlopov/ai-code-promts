# Visual Companion

Use only when seeing options is better than reading them.

Good use cases:

- UI mockups.
- Wireframes.
- Layout comparisons.
- Architecture diagrams.
- State flows.
- Visual hierarchy or spacing choices.

Bad use cases:

- Plain requirements questions.
- Text-only trade-offs.
- API design decisions.
- Scope clarification.

If accepted by the user:

1. Start the local server from `../scripts/start-server.sh`.
2. Write a new HTML file for every screen; never reuse filenames.
3. Ask the user to inspect the local URL and respond in chat.
4. Read browser events only as supporting context; terminal/chat feedback remains primary.
5. When returning to text discussion, show a waiting screen.

Do not use the visual companion without consent.
