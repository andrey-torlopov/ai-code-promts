# Evidence Rules

Use file-backed evidence for repository claims.

## Rules

1. Inspect real files before diagnosing, planning or reviewing.
2. Separate confirmed facts from assumptions.
3. Quote paths and line numbers when findings depend on specific code.
4. Do not generalize from a subset when the user asked for full scope.
5. If a scope is too broad to inspect completely, state exclusions and why.
6. For volatile external claims, verify current primary sources.
7. Do not invent commands, build systems, dependencies or conventions.
