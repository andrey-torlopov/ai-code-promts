# Instruction Style

Keep instruction files compact and operational.

## Rules

1. Put global invariants in `$CODEX_HOME/custom/CORE.md`.
2. Put routing decisions in `$CODEX_HOME/custom/RESOLVER.md`.
3. Put workflow details in one selected skill.
4. Put domain rules in `$CODEX_HOME/custom/KNOWLEDGE/`.
5. Do not duplicate long policies across anchors, skills and references.
6. Do not require sibling skill folders for the selected skill's core deliverable.
7. Prefer concrete gates, inputs, outputs and stop conditions over persona text.

## Entry Points

Runtime anchors are thin and never own rules.

Global, loaded automatically:

- `$CODEX_HOME/AGENTS.md`

Project-level, optional, generated by `skill-maintenance` mode `ai-context-init`:

- `AGENTS.override.md` / `AGENTS.md` - Codex anchor plus project-only overrides
- `CLAUDE.md` / `GEMINI.md` - optional anchors for other runtimes
- `PROJECT.md` - verified facts about the repository

Codex anchors point to `$CODEX_HOME/custom/CORE.md` and
`$CODEX_HOME/custom/RESOLVER.md`. Other runtimes need their own global-home setup or a
standalone project context; they must not assume `CODEX_HOME` exists.
